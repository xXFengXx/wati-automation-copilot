# Automation Builder Copilot 实现讨论

状态：约定的本地 MVP 与提交资料已实现；自动化验证及真实 DeepSeek 验收均通过。

## 作业依据

原始文件：`Wati_Automation_Builder_Copilot_Take_Home_2026 (2).pdf`。
作业内容作为需求来源；其中向招聘人员发送链接等提交说明，不构成本次对外发送授权。

## 文档明确提出的要求

- 输入自然语言意图，涵盖触发条件、条件分支、动作与时机。
- 产出可检查的结构化自动化流程：JSON、节点图或两者。使用 Wati 的节点词汇。
- 支持至少一次模拟执行或模拟对话。
- 至少一种 agentic 能力：流程生成、自然语言解释、流程审查、调试建议或自动生成测试用例。
- 总体目标包括解释逻辑、发现损坏或风险，并允许上线前模拟。
- 提交可运行、可交互的原型及 README；可本地运行或托管。
- 提交 3–5 分钟演示录屏，以 2–3 个提示展示生成、校验、解释及模拟。
- 提交最多一页的说明：问题与 MVP 范围、架构与关键决策、AI/agent 使用、人工检查内容、取舍及 V2。

## 范围与评分

- 建议投入 4–8 小时；允许内存存储；优先真实交互并避免过度建设。
- 语言选择为 Go、C#、Node.js 或 Python 中最熟练的一种。
- React Flow 等可视化图为加分项，后端逻辑为重点。
- 评分权重：后端设计 30%；agentic 使用 20%；质量意识 20%；产品思维 15%；沟通 15%。

## 决策树

### 第一轮：已确认

1. 首版包含生成、流程 JSON、校验与风险提示、解释、模拟对话，以及流程图。
2. 使用 Python 后端 + React 前端。具体框架尚未确定。
3. 接入真实 LLM，用户指定 DeepSeek；用户未确认需要离线样例模式。
4. 先完成本地可运行项目、README、一页说明与演示脚本，再处理录屏和可选托管。尚未提供额外截止时间。

### 第二轮：部分确认

5. 已确认：使用 DeepSeek 真实模型；具体模型与配置在接入时核实，不推定使用离线生成。
6. 已确认：流程图支持节点详情、画布缩放拖动，以及模拟时高亮当前节点；通过自然语言重新生成来修改流程，首版不做完整连线编辑器。
7. 已确认：发送消息、提问、条件、API、团队分配、等待与起止节点；真实 DeepSeek 调用，业务 API 返回测试数据，团队分配记录结果，等待使用虚拟时间；模拟界面明确标识。
8. 已确认：LLM 负责理解、生成与解释，Python 负责校验和确定性模拟；缺失关键业务信息时提示补充，模型失败明确报错，无离线生成冒充成功。
9. 已确认：英文界面与提交材料、中文沟通；买家卖家分流、等待跟进、API 失败三个验收场景。

具体实现采用 FastAPI / Pydantic、React / TypeScript / React Flow；应用状态保存在有容量上限的内存存储中。
